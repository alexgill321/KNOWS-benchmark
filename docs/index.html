Overview

KNOWS evaluates web agents on the work people actually do in Google Workspace: writing documents, building spreadsheets, and composing slide decks that require web research, multi-step tool use, and faithful grounding in retrieved sources.

Tasks are open-ended and realistic — an agent must find information on the live web, decide what matters, and produce a correctly structured, correctly formatted artifact. Every task ships with a programmatic evaluator that scores the finished artifact step by step, so agents are graded on the document they produced.

Hybrid, white-box evaluation

Each task's evaluator is an ordinary Python program that inspects the finished artifact through the Workspace APIs and its rendered form. Checks combine deterministic comparisons, tolerance-based matching, geometric layout tests, document-structure inspection, browsing-trace verification, and LLM/VLM judgements — whichever fits the criterion, rather than routing everything through a single model judge.

Step-level failure categories

Every scoring site in every evaluator records the mechanism that decided the step's outcome. Because categories are recorded on passing steps too, any run yields per-mechanism failure rates, separating genuine agent errors from judge-mediated failures, cascades, and harness faults.

deterministic
Exact text, numeric, regex, or pixel-exact comparison
fuzzy_match
Tolerance-based: fuzzy text, perceptual hash, numeric or color tolerance
llm_vlm_judgement
An LLM or VLM verdict decided the step
spatial
Geometric checks over rendered coordinates: bounding boxes, regions, coverage
structural
Document structure: element counts, ordering, position in the document tree
web_visit
Verification against the agent's browsing history
dependency_not_evaluated
Skipped because a prerequisite failed — a cascade, not a new error
execution_error
Missing data, unreachable source, or evaluator exception — a harness fault
vacuous_pass
Credit awarded although no check actually ran

Evaluators print a per-category summary alongside the score:

Getting started

The reference setup runs KNOWS through a BrowserGym fork; AgentLab provides the agent configurations used in the paper.

git clone https://github.com/farhanishmam/BrowserGym-Knows
cd BrowserGym-Knows
git submodule update --init --recursive   # pulls in the benchmark
# then follow the repo's README for installation and credentials

Evaluators are harness-agnostic: give your agent the task prompt plus a Google file it can edit, record the URLs it visits, and score the result from the repository root.

python src/browsergym/knows/eval/tasks/<family>/instance_<N>/evaluator.py \
  --workspace_doc_id "<FILE_ID>" \
  --browsing_history "https://example.com/a" "https://example.com/b"

The full protocol for any framework — provisioning, sharing, prompting, history capture, grading, and reading results — is in RUNNING_STANDALONE.md.

Maintenance and versioning

Tasks are curated to be time-agnostic and independent of any single website, but some reference live pages that can change. We verify the external sources our evaluators depend on at periodic intervals; if a change significantly alters a task's difficulty or solvability, we update the task or replace it with one of similar scope.

Every change ships as a new tagged release, and prior versions stay permanently available, so results reported against any version remain reproducible. Please report the benchmark version alongside your results. Outdated tasks and evaluator issues can be reported through the issue templates.
